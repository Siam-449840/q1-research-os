# Pilot study, November 2026: what the framework actually did on a real question

A real (small) computational study was run through Q1 Research OS v1.3 with Claude Code as the agent, to measure
time, automation and failure points. This is evidence about the framework, not a published paper.

**Question.** Does random cross-validation overstate how well cross-country cereal yield models transfer to unseen
countries and future years? Open data: FAO cereal yield and nitrogen use (via Our World in Data, CC BY 4.0) and
annual precipitation; 9,049 country-years, 170 countries.

**Scientific result (pre-registered decision rules).** H1 supported for gradient boosting: leave-country-out RMSE
1.929 t/ha vs 1.578 t/ha under size-matched random CV, +22.4 % (95 % country-block bootstrap CI 12.6 % to 35.7 %);
not supported for the linear model (+0.5 %). H2 (future years) not supported for either model. The independent
NumPy re-computation matched scikit-learn to 15 significant digits.

## What the pilot found in the framework (all fixed, with tests)

- OpenAlex chunked responses were silently truncated, so every OpenAlex search failed (fixed: small field selection
  and retry; failures still log nothing).
- A minus sign at the start of a results cell was dropped, so `-8.1%` was reported MISSING and `1.1%` falsely matched
  `-0.0107` (fixed; regression test).
- Two keyword false positives in protocol rules (classification rule fired on "diagnostics"; narrowed with a test).
- `CHOOSE` items needed a validated way to record a decision (added `rosctl cite-number`).
- The schema check caught a genuine data error: FAO nitrogen use up to 17,038 kg/ha for Faroe Islands.

## Honest limits of this measurement

- The time is the agent's wall-clock; no manual baseline was timed, so "hours saved" is not claimed.
- One small study, one domain, one agent; S8 and S9 untimed.
- Claude Code runtime findings: rules (CLAUDE.md) and skills were loaded and invoked correctly; the approval guard
  refused; **project permission rules were not active because the session was launched in a parent folder**
  (launch Claude Code inside the project folder).

## Update: owner approvals and independent review (S1, S2, S8)

- The owner approved S1 and S2 in the Claude desktop app terminal panel (process chain `zsh -> Claude Helper -> Claude`);
  the approval guard correctly treated it as the owner's terminal. Three usability problems surfaced and were fixed:
  typing `y` instead of `yes`, typing `yes` instead of the exact sentence `I APPROVE S1` (messages now say what is
  required), and running `rosctl` from a parent folder (it now prints the `cd` command for the project).
- After the freeze, all analyses were re-run as required; every number reproduced exactly and gates S3-S7 passed.
- **Independent review (S8)** was run with Antigravity's agent (Gemini 4 Argon, a different model family from the
  drafting agent), read-only, three roles in parallel (about 7 minutes; the reproducibility review timed out).
  Scores were 1-3 out of 5 on all 15 dimensions; the editor flagged desk-reject risk. The S8 gate blocked with
  30 blockers, as designed.
- **The most important finding:** the drafting agent wrote "There were no deviations from the protocol", but three
  pre-registered analyses (a sensitivity analysis, residual diagnostics, Holm adjustment) were never run, and the
  pre-registered reference baseline was omitted. No automated check caught this; the independent reviewer did.
  Other valid criticisms: invisible error bars (zero seed variance), figure numbering and caption, abstract-only
  literature with weak positioning, no reporting checklist, bootstrap median reported without saying so.
- Lesson: an AI draft that passes every machine gate can still be a weak paper. The human gates and the
  independent review are not optional extras; they are where scientific quality is actually decided. A planned
  control will make "every pre-registered analysis was executed" machine-checkable (protocol analysis IDs plus an
  execution ledger).

## Update: fix loop and second independent review

- **New control C59 (done):** pre-registered analyses carry IDs (A1, A2, ...), and `ledgers/PROTOCOL_EXECUTION.csv`
  records each one as `done` (result cell located in a logged output) or `deviation` (explained in the protocol).
  The S7 gate now blocks the pilot's original failure: an unexecuted analysis, or "no deviations" text while a
  deviation exists. Tests: 99; mutation testing: 33/33 killed; Python 3.9 and 3.13.
- **Fix loop (about 22 minutes of agent time):** the four omitted analyses were run under the frozen
  protocol (A3 reference baseline, A6 top-10% exclusion, A7 residual diagnostics, A8 Holm adjustment). Fig. 2 now
  shows country-block bootstrap CIs, and Fig. 1 (coverage) was added. The false deviation sentence was replaced by a
  Deviations paragraph, and a REFORMS checklist was added. Results: H1 holds for gradient boosting (gap 22.4%, 95% CI
  12.6-35.7%), but **it falls to 19.1% (16.4-22.0%) when the 17 highest-yield countries are excluded**, just below the
  20% decision threshold; the manuscript reports this as such. H2 is not supported.
- While fixing, the agent found that the "training-mean reference" had been computed as the in-sample mean of all
  data, not the pre-registered training-fold mean. It was corrected (2.391 / 2.394 / 3.179 t/ha for random /
  leave-country-out / forward) and logged as a deviation. C59 had passed the wrong version, because a locator can
  only prove that a number exists, not that the analysis matches the protocol's definition.
- **Second review (Antigravity, 4 roles in parallel, about 7 minutes, all completed):** scores rose from 1-3 to
  2-5, with 8 of 15 dimensions now at 4 or 5. The review found real problems the gates missed:
  - 28 rows of the number ledger pointed at stale manuscript line numbers (the check matched by value, not by
    location);
  - an import from outside the project;
  - an undocumented extension of the data to 2023;
  - figure axes clipping CIs;
  - an incomplete data-availability statement.

  These were fixed in about 6 minutes. One framework bug was also fixed, with a test: a deterministic re-run that
  rewrites identical bytes was never recorded, so an output could stay "STALE" forever.
- **S8 still fails (16 blockers), correctly.** The open major issues need the owner:
  - tuning parity / a regularised baseline (exploratory, outside the frozen protocol);
  - reading full texts legally instead of abstracts;
  - an independent re-computation of the gradient-boosting results and the bootstrap;
  - a persistent archive DOI;
  - committing the pilot;
  - crop-mix confounding.

  Positioning scores 2/5; significance, novelty, baselines, external validity, figures and journal fit score 3/5.
  All of these are below the bar.
- **Added afterwards (C60):** a provenance row's manuscript line must still contain its number; on a copy of the
  pilot, inserting one sentence flagged all 40 rows below it, and `rosctl provenance --apply` re-pointed all 40.
- **Still not checked by machine:** whether an analysis implements the protocol's definition (human review only).
